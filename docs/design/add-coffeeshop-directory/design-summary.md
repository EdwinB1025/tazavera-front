## 0. Settled inputs (not re-decided here)

- A **coffee shop is the business**: a user with role `coffeeshop` that owns one or more locations. Public `GET /coffeeshops` lists the coffee shops with at least one location (filters `name`, `city`, `postalCode`, `verified`; order by name; paginated like `/offerings`); `GET /coffeeshops/{user}` returns `{ ulid, name, locationsCount, offeringsCount, verifiedOfferingsCount, locations[ { ulid, name, description, latitud, longitud, address, city, postalCode, country, phone, web, social } ] }`. Business data only, never personal data (decisions log; refinement point 1).
- Header entry "Explora coffees" (decisions log).
- List with sidebar filters (name, postal code / district, with verified offerings; order by name), cards, pagination, with the catalog and facet patterns (decisions log).
- Map with **Leaflet and OpenStreetMap tiles**; a list/map toggle; a map icon on each card that centres that coffee shop's locations; full-screen map on mobile (decisions log; refinement point 1).
- Detail page with two tabs, "Ofertas" (`GET /offerings?coffeeshopUlid=<ulid>` with the catalog's filter sidebar) and "Ubicaciones" (its locations with a map), reusing the offering detail's tabs pattern (refinement point 2).
- CSP `img-src` opened to the tile servers — approved by Product owner (decisions log).
- Public reads are fetched on the server with plain `fetch` (settled data-loading rule); the map is client-only.
- Filters are facets in the sidebar (inverse controls), full screen on mobile, the order in the body (decisions log "filtros").
- The orchestrator chooses filters, library and behaviour by Product owner's delegation (decisions log "directorio de cafeterías").

## 1. Scope

1. `/{locale}/coffeeshops`: heading, toolbar (Filters trigger, view toggle, sort), list of coffee shop cards or the map, pagination; sidebar facets.
2. `/{locale}/coffeeshops/{ulid}`: back link, header with business data, tabs "Ofertas" (offerings list filtered by the coffee shop, catalog facets in the sidebar) and "Ubicaciones" (map + location cards).
3. Header entry "Explora coffees" → `/{locale}/coffeeshops`.
4. CSP `img-src` for `https://tile.openstreetmap.org`.

### 1.1 Capability

**`offering-catalog`** (public browsing), with deltas in `filtering` (the coffee shop facet set), `app-shell` (header entry, sidebar routes, CSP `img-src`). Justification: `config.yaml` rule "Reuse an existing capability before creating a new one"; the directory is the public catalog of coffee shops and its detail lists offerings with the catalog's own filter. The `offering-catalog` description needs one line (Open 1).

## 2. Out of scope

- Map clustering, geolocation of the visitor ("near me"), routing/directions, address search on the map (Nominatim autocomplete is forbidden by its policy anyway).
- District ("barrio") as its own filter: the API exposes no district field (Open 6).
- The offering detail's "Coffeeshop" caption linking to the coffee shop (Open 12).
- A mobile navigation for the header entries (finding 1).

## 3. Contract operations

| Operation | Method and path | Auth | Request | Response used | Errors and how they show |
|---|---|---|---|---|---|
| `listCoffeeShops` | `GET /coffeeshops` | none | `name` (max 150), `city` (max 90), `postalCode` (max 12), `verified` (`1`), `orderBy=name`, `orderDirection` (`asc` / `desc`, default `asc`), `page` | `data[]` coffee shops, each with its counters and **all its locations** (`ulid`, `name`, `description`, `latitud`, `longitud`, `address`, `city`, `postalCode`, `country`, `phone`, `web`, `social`); `meta` and `links` as the operation documents them | any non-2xx or transport failure → the list's one error state with "Try again"; any documented error response (a `422` included, if the contract lists one: **unverified**) → same |
| `getACoffeeShop` | `GET /coffeeshops/{user}` | none | path `ulid` | the resource of §0 | `404` (unknown) and any failure → the detail's one error state with back link and "Try again" (catalog D3 pattern: `found` / `not-found` / `failed`) |
| `listOfferings` | `GET /offerings` | none | the URL's offering facet keys (catalog D1 pass-through, offering-facets D4 sanitize) **plus `coffeeshopUlid` = the route's `ulid`**, forced, never taken from the URL | catalog D2 | catalog's states |
| `listOlfactoryTaxonomies`, `listCoffees`, `listRoasteries` | as `add-offering-facets` D1 | none | — | facet options | facet "Options unavailable" |
| OSM tiles (external) | `GET https://tile.openstreetmap.org/{z}/{x}/{y}.png` | none | — | images | a failed tile shows the map background; the list stays usable |

- The brief's `GET /offerings?locationId=` is corrected to the contract's name: `listOfferings` takes `coffeeshopUlid` (user ULID, line 5768) and `locationUlid` (line 5778). Refinement point 2 uses `coffeeshopUlid`.
- Each `listCoffeeShops` item carries all its locations with coordinates (contract description and example, lines 429–548; Open 2, closed), so the list's map, the card's map icon and the cities line read them directly.

### 3.1 Derived data

- The map points of a coffee shop: its `locations[]` with both `latitud` and `longitud` non-null, parsed from strings to numbers; label "{coffee shop name} — {location name}".
- The cities line of a card: unique `locations[].city` values in API order.

## 5. Behaviour, components, states and accessible names

### 5.1 Header entry

`PrimaryNav` gains "Explora coffees" (`exploreCoffeeshops`) → `/{locale}/coffeeshops`, between "Top rated" and "About us", with the existing item treatment, hover, focus ring and current-page bar (app-shell "Header brand and primary navigation"). Hidden below `md`, like the other entries (finding 1).

### 5.2 List page

- Heading block: eyebrow `listEyebrow` (`type-eyebrow`), `h1` `listHeading`, intro `listIntro`.
- Toolbar (body, catalog filter slot): `FiltersTrigger` (`add-offering-facets` D8, shared), the **view toggle**, and the sort field: a "Sort by" select (filtering "Sort control") with "Nombre (A–Z)" (`orderBy=name&orderDirection=asc`, default) and "Nombre (Z–A)" (`orderDirection=desc`) (Open 7, closed: the contract accepts `orderDirection`).
- View toggle: `ToggleGroup` (`src/shared/ui/ToggleGroup.tsx`, Radix) `type="single"`, named by `viewToggleLabel` ("Vista"), two items with icon + visible text: `List` "Lista" (`viewList`) and `MapIcon` "Mapa" (`viewMap`); exposed as pressed/not pressed; arrow keys move between items (Radix roving focus). Choosing writes `view=map` (or removes `view`) with `router.push(…, { scroll: false })`, keeping every other key; `page` is kept (the map shows the same page).
- **List view** (default): `CoffeeshopCard`s in **one centred column** (as the catalog list, add-offering-catalog round 1 point 4; refine-page-surfaces §5.5), `Pagination` (`@/shared/ui`, `path` + `query`), the catalog's loading (three skeleton cards), empty and error branches. Filtered empty: `noMatches` + "Clear all" (backlog R9; Open 5).
- **Map view**: the same page of coffee shops, every located location as a marker (§5.5); `Pagination` below the map; a line `unlocatedCount` (`type-meta`) under the map when some locations of the page have no coordinates. On viewports below `md` the map opens full screen (§5.6).
- Card map icon: activating it writes `view=map&focus={ulid}`; the map fits that coffee shop's located locations (one location → zoom 16, *my proposal*), their markers take the selected look and the first one's panel opens (§5.5). A `focus` value that is not on the current page is ignored.
- The result count announcement of `add-offering-facets` D9 (`resultCount`, visually hidden `role="status"`) is reused with `meta.total`.

`FacetPanel` titled `filtersTitle`, chips and "Clear all" (filtering "Applied-filter chips"); facets in order:

| Facet | Control | URL / API key | Limits |
|---|---|---|---|

### 5.5 Map (`LocationsMap`, shared, client-only)

- **Binding**: plain Leaflet in a `"use client"` component loaded through `next/dynamic` with `ssr: false` from a client module (the local Next docs: `ssr: false` is not allowed in Server Components). Library decision §6.
- **Tiles**: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, same in both themes (no filter; tiles are imagery, not gated). Max zoom 19.
- **Attribution**: Leaflet's own control disabled; an overlay at the map's bottom-right corner, `type-meta` on `surface-card`: "© {link}" with "OpenStreetMap contributors" → `https://www.openstreetmap.org/copyright` (native anchor, `LINK_CLASSES`). Always visible, never behind a toggle (tile policy).
- **Zoom**: Leaflet's control disabled; two `Button variant="action-4" size="sm"` icon-only buttons, `Plus` "Acercar" (`zoomIn`) and `Minus` "Alejar" (`zoomOut`), stacked at the top-right corner.
- **Markers**: one per located location; a Leaflet `divIcon` whose `html` is a DOM element built by the component (never an HTML string: app-shell "No injected raw HTML"), 2rem square, `rounded-pill` (0 in the dark theme, as every radius), fill `action-primary`, a 2px border `surface-card`, `MapPin` 1rem in `action-primary-text`; hover, keyboard focus and the selected look: fill `action-primary-hover`; `focus-visible:focus-ring`. Each marker is keyboard-focusable (Leaflet `keyboard: true`) and named "{coffee shop} — {location}" (`aria-label` on the element; Leaflet's `role="button"` on interactive markers **unverified** for 1.9.4 — set explicitly).
- **Selected location panel** (instead of Leaflet popups, which carry their own styles): activating a marker (click, Enter, Space) selects it and opens a `Card` overlaid at the bottom of the map: `h3` coffee shop name, `type-label` location name, `type-meta` address line ("{address}, {postalCode} {city}"), and `Link` "Ver cafetería" (`viewCoffeeshop`) → detail (client-side navigation, so the in-memory tokens survive); a close `Button variant="action-4" size="sm" icon={X}` `aria-label` "Cerrar" (`closePanel`). The panel is a `role="region"` named by its `h3`; opening it does not move focus; Escape closes it and returns focus to its marker. On the detail page's map the panel omits "Ver cafetería".
- **Container**: `role="region"`, `aria-label` `mapLabel` ("Mapa de cafeterías"), `aria-describedby` the visible help line `mapHelp` above the map ("Muévete con las flechas y acerca con + / −. La lista muestra la misma información."); the container is focusable with `focus-visible:focus-ring`; arrows pan, `+`/`-` zoom (Leaflet keyboard handler). The list view and the detail's location cards remain the accessible alternative (every map datum is also in text).
- **Bounds**: on load, fit all points (padding 2rem, *my proposal*); no points → the map is replaced by the text `mapEmpty` ("Ninguna de estas cafeterías tiene ubicación en el mapa.").
- **Loading**: until the client module loads, a placeholder of the map's size with `surface-section` and the `LoadingStatus` pattern (spinner + `loading`).
- **Reduced motion**: pan/zoom animations off under `prefers-reduced-motion` (Leaflet `zoomAnimation`/`fadeAnimation`/`markerZoomAnimation` false).

### 5.6 Full-screen map on mobile

Below `md`, `view=map` renders the map inside the existing `Sheet` (`src/shared/ui/Sheet.tsx`, Radix Dialog) as a full-screen overlay: title `mapLabel` (visually present, `type-subheading`) and a close `Button variant="primary" size="sm" icon={List}` "Volver a la lista" (`backToList`) in its header; closing (button or Escape) removes `view` (and `focus`) from the URL and returns focus to the toggle's "Mapa" item, or to the card's map button when opened from a card. Focus is trapped in the sheet while open (Radix). Pagination is not shown in the sheet; the page behind keeps it.

### 5.7 Detail page

- Back link `Link variant="back"` "Volver a cafeterías" (`backToList`) → `/{locale}/coffeeshops`.
- Header (as catalog D9's header block): `Badge verified` when `verifiedOfferingsCount > 0`, `h1` name, captions `type-label`: "{n} ubicaciones", "Ofertas: {n} · Verificadas: {n}".
- Composition: header block, tab bar and tab panels all on the page background (the backdrop, `PageSection surface="page"`); the tab bar does **not** sit in a `PageSection surface="section"` band (refine-page-surfaces §5.2: no section band in a feature view). Neither panel has sections with a header, so no section card is used; the content cards hang from the backdrop.
- Tabs (shared `Tabs`, catalog D6: `activationMode="manual"`, value in the URL, selection = navigation): "Ofertas" (`tabOfferings`, value `offerings`, **default**) and "Ubicaciones" (`tabLocations`, value `locations`); `?tab=`; unknown values show "Ofertas". "Ofertas" is the default so that "Clear all" (which keeps only the sort keys) never moves the user to another tab.
- "Ofertas" panel: the filtered-offerings widget of backlog R12 (Open 4, closed): the catalog's toolbar (`OfferingsToolbar`: Filters trigger + sort) and the offerings list in **one centred column** (as the catalog, round 1 point 4; never `CATALOG_GRID_CLASSES`) with its loading/empty/filtered-empty/error states and pagination (`path` = the detail route, `query` keeps `tab`), the request carrying `coffeeshopUlid`. The sidebar shows the eleven offering facets (`add-offering-facets`) on this tab only. The facets' City facet is kept (a coffee shop can have locations in several cities).
- "Ubicaciones" panel: the help line, `LocationsMap` (all located locations; panel without "Ver cafetería"), the `unlocatedCount` line when needed, then the `LocationCard`s (from `add-coffeeshop-location`) in one column. No sidebar on this tab.
- Loading: catalog D9's detail skeleton (back link, three bars, two skeleton cards). Error (`not-found` or `failed`): back link, message `detailError` and `RetryButton` (shared, catalog D4).

## 6. Library decision (approved direction, version to confirm)

Research: 3 registry look-ups + the tile policy + the local Next docs; candidates:

| Option | Version | License | Notes |
|---|---|---|---|
| **(A) `leaflet` alone**, wrapped in-house (one client component, `useEffect` creates and removes the map) + `@types/leaflet` (dev) | `leaflet@1.9.4` (dist-tag `latest`), `@types/leaflet@1.9.22` | BSD-2-Clause; types MIT | framework-agnostic, so React 19 / Next 16 compatibility reduces to client-only loading (`ssr: false`); ~40 kB gzip (**unverified**, from the project's public figures, not measured); accessible keyboard pan/zoom and focusable markers built in |
| (B) `react-leaflet` + `leaflet` | `react-leaflet@5.0.0` (peers `react ^19`, `react-dom ^19`, `leaflet ^1.9.0`; dep `@react-leaflet/core ^3`) | **Hippocratic-2.1** (not an OSI-approved license; adds ethical-use conditions) | idiomatic components; one more dependency and a license Product owner would need to accept |
| (C) `leaflet@2.0.0-alpha.1` | alpha | BSD-2-Clause | ESM-only rewrite, not stable: rejected |

**Recommendation: (A) `leaflet@1.9.4` + `@types/leaflet@1.9.22`**, behind `src/shared/lib/leaflet`. React 19 / Next 16: compatible by construction (no React peer). The map needs only markers, fit-bounds and keyboard, which do not justify (B)'s license and extra package. Sources: https://registry.npmjs.org/leaflet, https://registry.npmjs.org/react-leaflet/latest, https://registry.npmjs.org/@types/leaflet/latest. Building the map without Leaflet (SVG tiles in-house) is the third option and is not recommended (tile math, keyboard, gestures). Leaflet's stylesheet is imported once in the entry point (global CSS import from `node_modules` in the App Router: **unverified** for Next 16 — the architect checks the local docs at propose).

## 8. Layout and spacing (criterion A)

- Page: `PageSection surface="page"` (D14: 72rem container, 1rem/2rem side, 3rem/4rem vertical). Heading block: eyebrow, `h1` and intro stacked 0.5rem apart; 2rem to the toolbar.
- Toolbar: flex row, wraps, items aligned to the bottom, 1rem column gap / 0.75rem row gap; Filters trigger at the start, toggle next to it, sort at the end (`justify-between` between the start group and the sort); start group gap 1rem. No padding, border or radius. 1.5rem between the toolbar and the results.
- View toggle: inline flex, 0.5rem between items; each item min height 2.5rem, padding 0.5rem 0.75rem, 1px border (`action-3-border`), `rounded-field`, icon 1rem and label 0.5rem apart, `type-label`, `focus-visible:focus-ring`.
- Page background: the backdrop (`surface-page`, refine-page-surfaces); the body container is layout only; no `surface="section"` band anywhere in the directory (refine-page-surfaces §5.2).
- Results: one column of coffee shop cards, **no grid at any width** (`CATALOG_GRID_CLASSES` is not reused): the column has no width of its own and fills the `PageSection` container, so it is centred by construction, with the container's side padding (1rem below 768px, 2rem from it) as backdrop margins (refine-page-surfaces §5.5 and its width table); cards 1.5rem apart. Pagination 2rem below the list or the map (catalog), centred.
- Coffee shop card: card regions' own padding (1.5rem); inside `CardContent` a vertical stack 0.5rem apart (badge, name, locations, cities); footer as `OfferingCard`'s (counts 1rem apart; links group at the end, 1rem apart, wraps).
