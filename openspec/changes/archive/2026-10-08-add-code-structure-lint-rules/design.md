# Design

## Context

Backlog R39 ships the code-structure rules of AGENTS.md ("Architecture" and "Code structure") as ESLint warnings. Only ESLint 9 built-in rules are used; the only file that changes is `eslint.config.mjs`. Every new rule is `"warn"`; the existing `react/jsx-no-literals` entry and the `globalIgnores` stay as they are.

ESLint flat config replaces, not merges, the options of a rule when several config objects match the same file. The design therefore gives each file at most one effective `no-restricted-imports` entry: one base entry for `src/`, overridden by a more specific entry per layer or segment that repeats the base restrictions.

## Decisions

### D1. Size and complexity rules

- Rules: `max-lines` `{ max: 300, skipBlankLines: true, skipComments: true }`, `max-lines-per-function` `{ max: 80, skipBlankLines: true, skipComments: true }`, `complexity` `{ max: 15 }`, all `"warn"`.
- Why the options: the technical review counted non-blank, non-comment lines, so the limits are measured the same way. `max-lines-per-function` keeps its default `IIFEs: false`.
- Files: the production code, the same set the `react/jsx-no-literals` entry covers: `app/**/*.{ts,tsx}`, `src/**/*.{ts,tsx}`, `*.ts`.
- Ignores: `**/*.test.ts`, `**/*.test.tsx` and `src/shared/api/schema.ts`.
- Why the ignores: AGENTS.md sets the limits for components, functions and files of the code; tests are long by nature (one test per scenario with fixtures) and are not that code, and `qa/` holds only test files, so it is outside the globs. `schema.ts` is generated by `npm run types:api` and never edited by hand, so a warning on it could never be acted on.

### D2. No import between slices of the same layer

- Rule: `no-restricted-imports` with a `patterns` group `@/<layer>/*` and a message naming the rule, for each sliced layer: files `src/pages/**`, `src/widgets/**`, `src/features/**`, `src/entities/**`.
- Why every sliced layer and not only features: AGENTS.md states the rule for every layer ("between slices of the same layer"), and R39 asks for features "at least". The pattern also catches an import of the file's own slice through its public index, which D3 forbids too.

### D3. Inside a segment, never through its own public index

- A base entry over `src/**/*.{ts,tsx}` restricts the relative paths `.`, `./index`, `..` and `../index` (each re-enters the public index of the importing file's folder or of its parent slice or segment).
- A specific entry per non-sliced segment with a public index restricts its alias and its alias plus `/index`, together with the base relative paths: `src/shared/ui/**` → `@/shared/ui`; `src/shared/api/**` → `@/shared/api`; `src/shared/lib/<name>/**` → `@/shared/lib/<name>` for `filter-query`, `geocoding`, `hooks`, `i18n` and `leaflet`; `src/app/shell/**` → `@/app/shell`.
- The per-layer entries of D2 also repeat the base relative paths.
- Why an explicit list: no built-in rule can refer to the importing file's own folder, so each segment is named. A new segment with a public index adds its line to the list.

### D4. Test files outside the import rules

- Every `no-restricted-imports` entry ignores `**/*.test.ts` and `**/*.test.tsx`.
- Why: a test imports the slice or segment under test through its public API (for example `src/shared/ui/LoadingStatus.test.tsx` imports `@/shared/ui`), which is what the FSD skill asks for; it is not a production import.

## Risks

- The current code breaks the new rules in many places, so the lint run reports many warnings until R21–R38 land. The warnings are expected and not fixed in this change.
- A new segment with a public index is not checked by D3 until its line is added.
